# 企业应用迭代规划

这份规划用于把当前企业应用骨架继续推进成更完整的后端示例。每一阶段都保持可运行、可测试，不影响原有学习示例。

## 当前基线

- 已有 `cmd/server` 统一入口。
- 已有 Gin 路由、统一响应、请求 ID、CORS、请求日志和鉴权中间件。
- 已有用户注册、登录、任务创建、任务查询和任务完成接口。
- 已有内存仓储和 GORM/MySQL 仓储切换。
- 已有服务层、路由层、仓储工厂和鉴权基础测试。
- 已有 `scripts/check.ps1` 提交前检查脚本。

## 第一阶段：业务可用性（已完成）

目标：让用户和任务模块更接近真实业务系统。

| 任务 | 说明 | 验收方式 |
| --- | --- | --- |
| 用户资料查询 | 新增当前用户详情接口，例如 `GET /api/v1/me` | 已完成 |
| 任务归属隔离 | 当前用户只能查看和修改自己的任务 | 已完成 |
| 列表分页 | 用户列表、任务列表支持 `page`、`page_size` | 已完成 |
| 统一错误码 | 将业务错误码从 HTTP 状态码中拆出 | 已完成 |

## 第二阶段：外部基础设施（已完成）

目标：把已有中间件示例接入企业骨架。

| 任务 | 说明 | 验收方式 |
| --- | --- | --- |

## 第三阶段：认证与权限（已完成）

目标：从演示鉴权升级到更安全、更清晰的企业权限模型。

| 任务 | 说明 | 验收方式 |
| --- | --- | --- |
| JWT 或统一认证 | 将演示 Token 替换为 JWT 或认证服务适配层 | 已完成：HS256 JWT 与签名、过期、篡改测试 |
| 密码算法升级 | 将 SHA256 演示实现替换为 bcrypt 或 argon2 | 已完成：bcrypt 注册、登录测试 |
| 角色权限 | 增加管理员、普通用户角色 | 已完成：管理员用户列表访问控制 |
| 审计日志 | 记录登录、任务状态变更等关键操作 | 已完成：内存审计记录与单元测试 |

## 推荐推进顺序

1. 根据多服务场景评估 JWT 刷新、吊销或统一认证中心。
2. 为 Redis、RabbitMQ 增加可选端到端集成测试。

## 约束

- 默认运行路径必须不依赖 MySQL、Redis、RabbitMQ。
- 新增外部服务能力必须支持关闭或内存替代。
- 每个阶段至少补充单元测试或路由测试。
- 文档、注释和测试提示继续使用中文。
- 不把原有学习示例目录改造成重型项目，企业骨架保持在 `cmd/server` 和 `internal` 下演进。
